# Customer Management — Module 5

## Overview

Full CRUD for the `customers` table (defined in Module 2), with search,
filtering, sorting, pagination, and soft delete. Every endpoint requires
a valid JWT — since this CRM is single-admin (Module 3), any
authenticated user IS the admin, so no separate role check is layered
on top of `get_current_user`.

## Database changes

- Added `country` column (`VARCHAR(100)`, nullable) to `customers` — the
  Module 2 spec didn't include it, but Module 5's Add/Edit form requires
  it. Added via a new migration on top of the Module 2 migration, not by
  editing it.
  - Model: `backend/app/models/customer.py`
  - Migration: `backend/alembic/versions/20260817_0900_2a98345e2924_add_customer_country_column.py`

No other schema changes. `customer_code`, `phone` uniqueness, and soft
delete columns (`is_deleted`, `deleted_at`) already existed from Module 2.

## Customer code generation

Format: `CUS000001`, `CUS000002`, ... (`CUS` + 6 zero-padded digits).

Generated by reading the most recently inserted row's code (ordered by
`id`, which never decreases) and incrementing the numeric suffix. Since
soft-deleted rows are never removed from the table, a deleted customer's
code can never be reissued — the next generated code always advances
past it.

## Phone uniqueness

Enforced at two levels:
1. **Database**: `customers.phone` has a `UNIQUE` constraint (Module 2).
2. **Service layer**: `customer_service._check_phone_available()` checks
   proactively before insert/update, so the API returns a clean `409`
   instead of a raw database integrity error.

This check runs against **all** rows, including soft-deleted ones — a
deleted customer's phone number can never be reassigned to a new
customer, matching "phone numbers must always remain unique" combined
with "never permanently delete data."

## API

All under `API_V1_PREFIX` (default `/api/v1`), prefixed with `/customers`.
Every endpoint requires `Authorization: Bearer <token>`.

| Method | Path                | Purpose                                   |
|--------|---------------------|--------------------------------------------|
| POST   | `/customers`         | Create a customer                         |
| GET    | `/customers`         | List customers (search/filter/sort/paginate) |
| GET    | `/customers/{id}`    | Get one customer                          |
| PUT    | `/customers/{id}`    | Update a customer                         |
| DELETE | `/customers/{id}`    | Soft-delete a customer                    |

### POST /customers
```json
{
  "full_name": "Aarav Mehta",
  "phone": "+91 98765 43210",
  "email": "aarav@example.com",
  "company": "Mehta Traders",
  "city": "Mumbai",
  "state": "Maharashtra",
  "country": "India",
  "notes": "Interested in the enterprise plan.",
  "status": "active"
}
```
- `201` → the created customer (with generated `customer_code`)
- `409` → phone already in use
- `422` → validation failure (missing name/phone, bad email/phone format)

### GET /customers
Query params (all optional except pagination defaults):

| Param        | Type    | Notes                                              |
|--------------|---------|------------------------------------------------------|
| `search`     | string  | matches name, phone, email, or company (partial, case-insensitive) |
| `status`     | enum    | `active` / `inactive` / `blocked`                  |
| `city`       | string  | partial, case-insensitive                          |
| `state`      | string  | partial, case-insensitive                          |
| `sort`       | enum    | `newest` (default) / `oldest` / `name_asc` / `name_desc` |
| `page`       | int     | default `1`                                        |
| `page_size`  | int     | default `10` (fixed per spec; max `100`)           |

Response:
```json
{
  "items": [ /* CustomerOut[] */ ],
  "total": 42,
  "page": 1,
  "page_size": 10,
  "total_pages": 5
}
```
Soft-deleted customers are always excluded.

### GET /customers/{id}
- `200` → full customer details
- `404` → not found (or soft-deleted)

### PUT /customers/{id}
Same body shape as POST (full-form update, not a partial patch).
- `200` → updated customer
- `404` → not found
- `409` → phone already in use by a different customer
- `422` → validation failure

### DELETE /customers/{id}
- `200` → `{ "message": "Customer deleted successfully." }`
- `404` → not found

Soft delete only — sets `is_deleted = true`, `deleted_at = now()`. The
row is never removed from the database.

## Validation rules

| Field         | Rule                                                          |
|----------------|------------------------------------------------------------------|
| Customer Name  | required, trimmed, 1–150 chars                                |
| Phone Number   | required, trimmed, must look like a phone number (digits + `+ - ( ) space`, ≥7 digits), unique |
| Email          | optional; if provided, must be a valid email format            |
| Company/City/State/Country | optional, trimmed, blank → stored as `null`         |
| Notes          | optional, trimmed, up to 5000 chars                            |
| Status         | one of `active` / `inactive` / `blocked`, defaults to `active` |

Enforced in two places, sharing the same rules:
- **Backend**: `app/schemas/customer.py` (Pydantic validators, reusing
  `app/utils/validators.py`) — the source of truth
- **Frontend**: `utils/validators.js` (`isValidEmail`, `isValidPhone`) —
  instant UX feedback only; the backend re-validates independently

Add and Edit share one form component (`CustomerFormModal.jsx`) and one
validation path, per "reuse existing validation."

## Call button

`ActionButtons.jsx` (built in Module 4) already accepted an `onCall`
prop and rendered it disabled when absent. Module 5 passes a real
handler for the first time — `CustomersPage.handleCall` — which shows
the toast "Voice Calling will be available in Module 9." No change to
`ActionButtons.jsx` itself was needed: a future module makes Demo
Call / Real Call work by changing what `handleCall` does, not by
touching the button's markup.

## Manual testing steps

**Backend (curl)** — replace `<token>` with a value from `POST /auth/login`:
```bash
BASE=http://localhost:8000/api/v1

# Create
curl -X POST $BASE/customers -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"full_name":"Aarav Mehta","phone":"+91 98765 43210","email":"aarav@example.com","status":"active"}'

# Duplicate phone — expect 409
curl -X POST $BASE/customers -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"full_name":"Someone Else","phone":"+91 98765 43210","status":"active"}'

# List with search/sort/pagination
curl "$BASE/customers?search=Mehta&sort=name_asc&page=1" -H "Authorization: Bearer <token>"

# Get by id
curl $BASE/customers/1 -H "Authorization: Bearer <token>"

# Update
curl -X PUT $BASE/customers/1 -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"full_name":"Aarav Mehta","phone":"+91 98765 43210","status":"inactive"}'

# Soft delete
curl -X DELETE $BASE/customers/1 -H "Authorization: Bearer <token>"

# Confirm it's gone from the list
curl "$BASE/customers" -H "Authorization: Bearer <token>"

# No token — expect 401
curl $BASE/customers
```

**Frontend**
1. Log in, click **Customers** in the sidebar.
2. Empty state: with no customers, see "No customers found." + Add Customer button.
3. Add a customer with all fields filled — see the "Customer Added" toast, new row appears.
4. Try adding another customer with the same phone — see inline field error + "Duplicate Phone Number" toast.
5. Leave Customer Name blank and submit — see inline error + "Validation Error" toast.
6. Click **View** on a row — modal shows full details.
7. Click **Edit**, change a field, Save — see "Customer Updated" toast, row reflects the change.
8. Click **Delete** — confirm dialog appears; confirm — see "Customer Deleted" toast, row disappears.
9. Click **Call** — see "Voice Calling will be available in Module 9." toast.
10. Type in the search box — list filters live (name/phone/email/company).
11. Filter by Status/City/State — list narrows accordingly.
12. Change Sort — order changes (Newest/Oldest/Name A-Z/Name Z-A).
13. Add 11+ customers — pagination controls appear, 10 per page.
14. Resize the browser through mobile/tablet/laptop/desktop — table scrolls horizontally on narrow screens, filters/modals reflow correctly.
